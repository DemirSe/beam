# ADR 0002: TOML configuration

## Status

Accepted.

## Context

The current stock Xray deployment uses a small JSON configuration. The new
server needs a configuration format that is easy to review, comment, validate,
and generate. Existing Xray JSON compatibility is not required; wire
compatibility with clients is.

## Decision

Use TOML for the native configuration format. Unknown fields are errors. The
schema is deliberately small and covers only the production profile.

## Consequences

- Comments and explicit types make hand-editing and AI generation safer.
- `serde` + `toml` provide strict decoding and useful error locations.
- Existing Xray JSON files are not imported.
- A converter can be added later if migration becomes useful, but it is not a
  first-release requirement.
