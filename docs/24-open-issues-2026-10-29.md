## P0 — verify before changing policy

1. **Listener backlog is effective; do not change sysctls yet.**
   Production has `net.core.somaxconn=4096`, `ss -lnt :443` shows backlog
   **1024**, and `net.ipv4.tcp_max_syn_backlog=128` with
   `tcp_syncookies=1`. The 128 value is the separate half-open/SYN queue, not
   the accept backlog. `ListenOverflows=102` is a lifetime count over six days,
   not a current baseline. Measure accept-queue bursts and SYN pressure
   separately in the lab; raise sysctls only if a delta under realistic load
   shows overflows. A one-byte slowloris flood tests the accept queue, not
   specifically the SYN queue.

2. **Per-IP pre-auth 128 is sound for this single-user deployment.**
   It bounds one source to 128 of 256 handshake slots; steady-state
   authenticated connections are not affected because the pre-auth permit is
   released after ClientHello classification. Per-subnet accounting or an
   authenticated reserve is not justified by current evidence. Document the
   same-NAT trade-off rather than change the code.

3. **24-hour soak remains open; 10k churn is complete.**
   10k churn passed on the final branch (10,000/10,000, fds 12→12, threads
   2→2, RSS 7,916→9,048 KiB). The 24 h mixed TCP/UDP/DNS/QUIC soak,
   privileged syscall/wakeup/splice gates, and cgroup socket-memory/OOM
   sampling remain a wall-clock release gate; do not compress it.

## P1 — confirmed code defects

4. **XUDP control-frame enqueue can block a mux.**
   `send_end` waits up to `io_timeout` (live 10 s) when the outbound queue is
   full (`xudp/session.rs:779-800`). The reply-task error path has the same
   await (`:827-838`), and `close_active` waits for that task
   (`xudp/server.rs:730-733`). One slow reader can head-of-line block all
   sessions on that mux. Fix **both** End paths with a FIFO-preserving small
   control reservation plus a short bounded fallback and a drop counter. Do not
   let End overtake accepted data, and do not silently assume dropping End is
   protocol-transparent. Tests: ordering, slow-reader recovery, session-ID
   reuse, permit release, unrelated-session progress.

5. **Cover relays use twice the dial budget.**
   `forward_to_cover` passes `config.handshake_timeout` (live 10 s) to dial and
   write (`tls/server.rs:1011-1012`); authenticated dials cap at
   `MAX_DIAL_TIMEOUT=5 s` (`:873`). A cover outage can pin the 32 cover slots
   for 10 s. Clamp both to 5 s; add a cover-outage test. Low production risk,
   small fix.

6. **`IpLimiter` has a documented zero-limit mismatch.**
   `max_per_ip=0` admits one permit per new source (`admission.rs:59-63`)
   instead of rejecting every source as the docstring says. Production
   validation rejects zero, so this is latent. Add the early `PerIp` reject and
   a unit test. The `Drop` subtraction (`:86`) is invariant-protected and has no
   reproduction; do not label it a live bug or mask corruption silently.
   IPv4-mapped canonicalization is future dual-stack hardening, not a current
   IPv4-only issue.

7. **XUDP pressure metrics are missing.**
   Only `preauth_rejected`, `cover_limited`, `connection_limited`, and
   `accept_errors` exist. Add narrowly scoped counters/gauges for XUDP
   admitted/rejected/evicted/dropped, legacy-UDP limit, splice fallback, and
   active pre-auth/authenticated slots in the existing 60 s log. Keep the stats
   API out of scope. Add metrics before tuning fairness or capacity.

8. **Stale capacity comment.**
   `main.rs:36-37` says `~80 pairs`; the 120 splice permits correspond to ~60
   fully spliced pairs. This is a comment fix only. Async fallback means 60 is
   not a connection ceiling; historical 512/1024 bulk timeouts do not prove
   that epoll/io_uring or a lower admission cap is the required remedy.

## P1 — protocol decision, not a release blocker

9. **TLS-fragmented ClientHello is now reassembled (final branch).**
   `read_client_hello_record` accepts up to four records under one absolute
   pre-auth deadline, including a 1–3 byte split of the four-byte handshake
   header. It normalizes the assembled handshake to one record for
   `ClientHello::parse`/rustls and preserves original wire bytes for cover
   fallback. Bounds: handshake ≤ `MAX_CLIENT_HELLO_LEN`, normalized record ≤
   configured bound, wire ≤ configured bound + three record headers, same
   deadline. Tests cover split-body, split-header, and single-record paths.
   Auth AAD remains the reassembled CH handshake bytes; no transcript change.

10. **Timestamp skew is currently disabled by policy.**
    Runtime passes `None` for `max_time_diff` (`beam/src/main.rs:301`;
    `reality/auth.rs:326-328`). Tests must distinguish "checking disabled" from
    "old timestamp rejected"; do not quietly introduce a freshness policy.
    Add replay, skew, max-size record, and post-Direct Record/KeyUpdate tests.

11. **Fully framed Vision upload is a client/protocol limitation.**
    Raw read is gated on client `Direct`; while the client sends outer
    ciphertext the server must decrypt and frame. Forcing raw or forging inner
    `100 Continue` breaks TLS/interop. Add a 1 GiB POST with and without
    `Expect: 100-continue` as documentation/lab evidence; do not change the
    protocol.

12. **Cover parity: closed by decision (2026-10-29).**
    SNI, certificate, TLS 1.3/PQ group, and cipher behavior are sufficient.
    Plaintext extension order and encrypted-flight size may differ; this is not
    a defect and does not block deployment. Keep the capture harness
    diagnostic, and do not pursue custom TLS for byte parity.

## P2 — measurement, fairness, lab hygiene

13. **XUDP fairness is implemented in the final branch.**
    Each mux stream may hold at most half the global slots (production 128 of
    256); retained-to-active reattachment is subject to the same cap, and a
    rejected reattach leaves the retained socket available. Retained eviction
    now selects the globally earliest expiry and revalidates under the selected
    table lock, rescanning on concurrent invalidation. Tests cover one-stream
    monopolization, global rejection across three streams, and global oldest
    eviction. The cap is policy, not a security boundary; tune only with
    pressure data.

14. **Half-close failure has no established root cause.**
    `edge_half_close` is 0/40 on both beam and stock Xray, so there is no
    beam-only regression. The repo spec says a TCP FIN should end one direction
    without closing the other (`docs/08-vision-xudp-spec.md:69-74`), and beam
    handles FIN (`tls/server.rs:1408-1411`). The shared client/TUN path is
    plausible, not proven. Add a direct-to-target baseline and richer probe
    diagnostics before attributing it to VLESS/Vision.

15. **UDP failures have two different causes.**
    Zero-length datagrams are dropped by design in XUDP (`xudp/session.rs:739-741`),
    not by MTU. Payloads ≥1473 B are consistent with the shared TUN MTU 1500
    boundary, but the exact drop point is unproven. Keep both out of the
    beam-regression column; add direct-target and SOCKS/UDP isolation probes.

16. **Benchmark claims are provisional.**
    The 1.023x/1.333x results are n=3 and were not confirmed by the 5-rep
    old/new rerun on 2026-10-29 (neutral within noise; see Verification). The
    1.333x median is not carried by the outlier (samples 1271.8, 1280.0,
    1561.2; median 1280.0), but n=3 remains weak. CPU accounting uses cgroup
    for beam and `schedstat` for Xray; TTFB direction is credible, magnitude is
    not final. Re-run n=10 with matched CPU source, per-rep frequency, paired
    wins and uncertainty. Treat capacity as a design limit: 120 splice permits
    means ~60 fully spliced pairs, with async fallback; do not raise the
    160-thread pool on 1 GiB.

## Applied XUDP fix — 2026-10-29

`1c0d00e4d0eba1c41b8acd190e18f3b3852f563a9c4e6091ea6ad9e57d832f4d`.
