# Open issues after admission hardening — 2026-10-29

Status: notes for the next work session. The admission-hardening binary

this file is fixed yet.

## P0 — verify before the next production change

1. **Kernel backlog may cap the new 1024 listener backlog.**
   `limits.listen_backlog=1024` is now applied, but the production host still
   has the old `net.core.somaxconn` / `tcp_max_syn_backlog` values (128 at the
   2026-10-24 audit). Check the live values and `ListenOverflows`; raise the
   sysctls only with a measured need. Verify `ss -lnt` shows 1024 after deploy
   and that the kernel does not silently clamp it.

2. **Per-IP pre-auth limit has a same-NAT trade-off.**
   Default `max_preauth_per_ip=128` protects different source IPs, but one
   source can still consume its own 128 slots and affect users behind the same
   NAT/IP. Decide whether 128 is the right default for the single-user profile;
   consider per-subnet accounting or an authenticated-path reserve.

3. **24-hour soak and 10k churn are still open.**
   Release acceptance requires a final-binary 24 h mixed TCP/UDP/DNS/QUIC run,
   fd/RSS/thread/pipe sampling, and 10k connection churn. Also run the
   privileged syscall/wakeup/splice gates on a quiet host.

## P1 — protocol and real-world extremes

4. **Vision Direct fully framed uploads remain on the async path.**
   Clients that send the whole body framed (no early `Expect: 100-continue` or
   Direct block) do not get the raw handoff. The issue is client-controlled;
   a server change would require a protocol decision. Add a lab test
   (1 GiB POST with and without `Expect`) and document the limitation.

5. **Large HTTP/3 + loss/jitter is not covered.**
   The suite only exercises small H3 bodies. Add 64 MiB H3, parallel streams,
   1–3% loss, and 50 ms jitter. Current known failures are QUIC PTO/TCP HOL,
   gVisor stalls, and TUN MTU 1500; UDP/QUIC is not covered by the target MSS
   clamp.

6. **XUDP pressure is not stress-tested.**
   `max_xudp_sessions` is configurable (default 256), but 256/512-session
   floods, 2048 destinations, retained-GlobalID eviction, and slow-reader reply
   backpressure have no lab matrix. No XUDP counters were added; only
   admission/cover counters exist.

7. **Fragmented ClientHello / replay / record-boundary tests are missing.**
   Auth probes cover wrong UUID, short ID, SNI, garbage TLS, and recovery.
   Add 1-byte-fragmented ClientHello, max-size records, replay of an
   authenticated session ID, timestamp skew, and post-Direct Record/KeyUpdate
   cases.

8. **TLS/REALITY cover parity gaps remain.**
   Extension order (`key_share`/`supported_versions`) and encrypted-flight
   size still differ from the live cover. The recaptured 2026-10-28 artifact
   is 3503 B / 4 records vs the documented 4305 B / 5 records. Decide whether
   to pursue byte-level parity or document the residual distinguisher.

## P2 — capacity / observability / lab hygiene

9. **Admission capacity is still admission, not bulk capacity.**
   `max_connections=1024` and the 160-thread blocking pool still cannot carry
   1024 bulk Vision relays; historical 512/1024×1 MB loads produced long
   latencies/timeouts. A real fix needs epoll/io_uring or a lower admission
   cap. Do not raise the pool blindly on 1 GiB.

10. **Observability is incomplete.**
    Admission counters are logged every 60 s, but there are no XUDP
    session/eviction/drop counters, relay/accept-queue gauges, or memory
    metrics. A stats API remains out of scope; extend structured counters/logs.

11. **Half-close lab probe fails on both arms.**
    `edge_half_close` returned 0/40 for beam and stock Xray. This looks like a
    probe/target behavior issue, not a beam regression, but it must be fixed
    before trusting that row.

12. **Large UDP datagrams and zero-length probes fail on both arms.**
    `udp_zero` and payloads ≥1473 B fail for beam and stock Xray. This is the
    shared client/TUN MTU limitation, not proven beam behavior; keep it in the
    shared-limitation section, not as a regression.
