# Hardening pass, 2026-11-11

Actions-only audit of the beam server. Every claim below was produced by a GitHub
Actions run in this repository: a finding is first reproduced red, then documented,
then fixed, then proven green. Nothing was executed on the production host, and no
local binary was run.

Branch: `dev`. Deployment is untouched by this pass.

## Method

- Each experiment is a throwaway branch with its own workflow and probe script, so
  a run is reproducible from its commit alone.
- `dev-audit` (`.github/workflows/dev-audit.yml`) now runs format, clippy, and the
  full workspace suite on every push, with `pipefail`, so a failing suite cannot
  masquerade as a green step.
- Probes prefer the real client: `tests/stress/vless_client.py` starts beam and a
  pinned sing-box (v1.14.4, checksum-verified) and derives the REALITY public key
  from the example fixture with a pure-Python X25519 implementation that carries
  the RFC 7748 known-answer test.

## F1 — mux teardown skipped on cancellation (fixed)

**Proven red.** `aborting_the_mux_handler_releases_sessions_and_permits` aborts a
live mux handler that owns three sessions. Before the fix (run 42926928710):

```
assertion `left == right` failed: aborted mux left sessions registered:
XudpStats { max: 8, available: 5, used: 3, high_water: 3, active: 3, retained: 0,
            live_tables: 1, live_handlers: 0, unattributed: 0 }
  left: 3
 right: 0
```

`live_handlers: 0` proves the handler was gone; `active: 3` and `used: 3` prove the
sessions, their sockets, and three global permits outlived it. Cause: the
drain/stop/join teardown ran only when `read_loop` returned, so a cancelled task
(runtime shutdown, a panic) skipped it and the reply tasks kept everything alive.

**Fix.** `MuxTeardown` is registered for the handler's whole lifetime and, on
drop, drains the table, clears retained sockets, claims and stops each session,
releases its permit, and aborts its reply task. The return path is unchanged and
idempotent.

**Proven green.** Same test after the fix (run 42927245182, `dev-audit` success):

```
test result: ok … 0 failed
```

Documented in `STATE-MACHINES.md` (register, one-page summary, machine 14,
cross-cutting notes).

## I1 — replay rejections are now counted

`STATE-MACHINES.md` called the missing replay-rejection counter the clearest
missing operator signal: a ClientHello that finishes TLS and then loses the
first-wins race, or arrives with a full cache, was visible only as a debug line.
`replay_rejected` is now incremented where `replay_insert` fails, appears in the
pressure warning and the periodic counter line, and the counter tuple's new index
is pinned by a test.

## Separate finding that was withdrawn

An empty-payload `Keep` that carries a destination does not retarget the session.
A first report called this a defect; Sol reviewed it against upstream Xray
(`handleStatusKeep` passes that frame's target to a new packet reader, with no
persistent update) and sing-vmess (the writer repeats the destination on every
packet) and returned **NOT A BUG**. The behaviour is now documented precisely in
`README.md` and pinned by four tests instead.

## Not a defect: client-initiated FIN through sing-box

A client that sends its payload and half-closes is dropped rather than served:
sing-box resets the stream instead of propagating the FIN, and beam then sees
`Connection reset by peer`. The relay's own half-close handling is exercised with
a target-initiated FIN instead, which passes. Documented here so the next person
does not file it as a beam bug.

## New permanent gates

`tests/stress/vless_client.py`, `vless_interop.py`, `vless_halfclose.py` and
`config_matrix.py`, wired as push gates on `dev` and `main`:

- `interop.yml` — authenticated end-to-end path for both datagram encodings, plus
  half-close, with a checksum-pinned sing-box.
- `config-matrix.yml` — 57 boundary and malformed configurations, `--check` must
  never panic or hang.
- `dev-audit.yml` — fmt, clippy, and the full suite on every push, with
  `pipefail` so a failing suite cannot report a green step.

## Open items after this pass

- Client-initiated FIN is unverifiable through the current harness (sing-box
  resets); verifying it needs a client that propagates half-close.
- XUDP oversize frames close the mux by design; the client contract is 8192
  bytes and this is not a defect, but operators should know a buggy client can
  drop its own mux.
- Fuzz campaign: all seven targets ran ten minutes each under ASAN (run
  42928333509) with no crash.
- The transport matrix is covered: Vision and plain flow, each with xudp,
  packetaddr and legacy VLESS UDP, all byte-exact (run 42930039966).
